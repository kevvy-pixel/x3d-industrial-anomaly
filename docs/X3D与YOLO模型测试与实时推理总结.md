# X3D 与 YOLO 模型测试及实时推理总结

## 一、数据划分和训练流程

### X3D 四分类

- 类别：`normal`、`single_hand`、`board_drop`、`touch_face`。
- 先按原始视频划分，再生成片段，避免同一视频的片段同时出现在训练集和验证集。
- 共 1065 个源视频：852 个训练视频、213 个固定验证视频。
- 固定验证清单：`D:\CondaData\factory_x3d_m\experiment\val_sources.csv`。
- X3D 输入为 16 帧、224×224 RGB 视频片段。
- 约 16/24/30 FPS 分别使用 1.0/0.8/0.7 秒窗口，并在窗口内均匀抽取 16 帧。
- 训练时四类等量采样，每个 epoch 每类取 91 个样本，防止 normal 样本过多主导训练。
- 最终训练样本：训练集 7921 个，验证集 1983 个。

### X3D 二分类

- 类别：`normal`、`touch_face`。
- 完全复用四分类的源视频划分，没有重新随机划分。
- 原 `normal`、`single_hand`、`board_drop` 都作为二分类中的 normal，后两类作为摸脸硬负样本。
- 训练集：normal 7600、touch_face 321；验证集：normal 1890、touch_face 93。

### YOLO 四分类项目

该项目并非单一 YOLO 四分类模型，而是：

```text
板检测 YOLO + 手检测 YOLO + 姿态检测 YOLO
→ 81 维行为特征
→ MLP 时序分类器
→ Viterbi 状态解码
```

README 记录为 1065 段视频，851 段训练、214 段验证，按“数据源×类别”分层。每个数据源同时出现在训练和验证中，划分方式与 X3D 的源视频隔离不同，也没有看到独立盲测集。

## 二、本地测试结果

### 1. X3D 四分类

验证集总体指标：

| 指标 | 结果 |
|---|---:|
| Accuracy | 92.59% |
| Macro-F1 | 80.29% |

| 类别 | Precision | Recall | F1 |
|---|---:|---:|---:|
| normal | 99.57% | 92.63% | 95.97% |
| single_hand | 56.16% | 97.62% | 71.30% |
| board_drop | 69.70% | 82.14% | 75.41% |
| touch_face | 70.69% | 88.17% | 78.47% |

判断：`normal` 表现最好；`single_hand` 召回率高但误报多；`board_drop` 验证样本只有 28 个，结果不稳定；`touch_face` 中等，仍存在误报。

### 2. X3D 二分类

默认阈值 0.5 下：

| 指标 | 结果 |
|---|---:|
| Accuracy | 97.98% |
| Macro-F1 | 89.57% |
| ROC-AUC | 95.09% |
| PR-AUC | 84.34% |

| 类别 | Precision | Recall | F1 |
|---|---:|---:|---:|
| normal | 99.36% | 98.52% | 98.94% |
| touch_face | 74.31% | 87.10% | 80.20% |

阈值约 0.684 时，`touch_face` 的 Precision/Recall/F1 为 79.38%/82.80%/81.05%。实时部署使用约 0.65～0.68，并叠加平滑和连续确认。

判断：二分类整体优于四分类，但 touch_face 的 Precision 仍不够高，现场长时间运行仍可能产生误报。

### 3. YOLO + MLP 四分类

README 记录的帧级 Macro-F1 为 0.783。事件级指标为：

| 行为 | Precision | Recall | F1 |
|---|---:|---:|---:|
| single_hand | 75% | 97% | 0.85 |
| touch_face | 78% | 90% | 0.84 |
| board_drop | 100% | 88% | 0.93 |

该项目没有给出可与 X3D 直接对应的总体 Accuracy，也没有 normal 的事件级 P/R/F1。data2 的 65 段纯 normal 视频记录为零误报，但 data3 异常样本很少，结果不稳定。

判断：YOLO 项目的 `board_drop` 事件指标最好，但现场仍有远距离漏检、single_hand 与 board_drop 混淆，以及无 GPU 时卡顿的问题。

## 三、本地测试与实时推理的差异

两者属于同一业务方向，但不是完全相同的任务：

- 本地测试是人工标注短窗口的分类；窗口通常已经覆盖主要动作，且标签明确。
- 实时推理是连续视频上的在线事件检测，需要处理动作开始、结束、过渡、遮挡和长时间 normal 背景。
- X3D 实时推理默认每 0.3 秒运行一次，使用 16 帧滑动窗口、3 窗口概率平滑和连续 2 窗口确认。
- YOLO 离线评估使用整段视频的 Viterbi 解码，能够利用后续帧；实时推理只能使用当前和过去帧。
- 实时系统还受到 RTSP 解码、帧率波动、GPU/CPU 性能、缓存延迟和报警视频编码影响。

## 四、为什么本地效果较好而现场效果较差

1. 离线窗口是按标注切出的，现场包含大量动作过渡和困难负样本。
2. 验证集 normal 占比很高，Accuracy 会被 normal 类抬高，不能代表异常事件的实际效果。
3. 现场摄像机角度、距离、光线和人物大小与训练数据不完全一致；人物变小后，尤其容易漏检。
4. X3D 的平滑和连续确认会减少瞬时误报，但可能增加延迟、漏掉短动作。
5. YOLO 依赖板、手和姿态检测，前置检测失败会直接导致行为分类失败；CPU 环境下还会出现卡顿和采样变稀。
6. 当前没有带人工标注的连续现场 RTSP 验收数据，因此无法把离线 Accuracy 直接换算成现场事件召回率或每小时误报率。

## 五、最终结论

- X3D 四分类已经完成较严格的源视频级固定验证，但主要问题是异常类别误报，尤其是 `single_hand`。
- X3D 二分类的离线结果最好，适合单独强化摸脸识别，但不能把 97.98% 当作现场保证准确率。
- YOLO + MLP 的 `board_drop` 事件指标较好，但其验证划分和 X3D 不完全一致，现场仍存在距离、角度、类别混淆和性能问题。
- 目前三种模型都只能说明“在固定本地测试集上有效”。正式验收应使用甲方连续 RTSP 视频并人工标注，统计事件召回率、误报次数、漏报次数、报警延迟和短动作漏检率。
